3 approches pour migrer vers le SaaS

La question centrale : comment intégrer Supabase dans une app aujourd'hui 100 % locale ?

A

Progressive — sync optionnelle (recommandé)

IndexedDB reste la source de vérité pour les utilisateurs gratuits. Supabase s'ajoute comme couche de sync pour les Pro.

Non connecté → IndexedDB (comme aujourd'hui)
Gratuit (1 projet) → IndexedDB + compte Supabase
Pro → IndexedDB + sync Supabase automatique

Avantages

  • Moteur existant inchangé
  • V1 livrable en 3-4 semaines
  • Fonctionne hors ligne

Inconvénients

  • Double source de vérité à gérer
  • Sync à implémenter soigneusement
B

Cloud-first — Supabase comme seule source

On remplace IndexedDB par Supabase. Tous les utilisateurs ont un compte, même gratuits. Architecture plus propre.

Tout utilisateur → compte requis → projets dans Supabase
Gratuit → limité à 1 projet en base
Pro → illimité

Avantages

  • Architecture simple et cohérente
  • Pas de sync à gérer
  • Multi-appareil natif

Inconvénients

  • Nécessite internet en permanence
  • Migration IndexedDB existante à prévoir
  • Compte obligatoire dès le départ
C

Offline-first PWA — cache local + sync différée

IndexedDB reste le cache local. Un Service Worker synchronise avec Supabase quand la connexion est disponible. App installable.

Modification locale → IndexedDB
Quand online → sync automatique → Supabase
Conflit → résolution last-write-wins

Avantages

  • Fonctionne sur chantier sans réseau
  • App installable (PWA)

Inconvénients

  • Complexité élevée (gestion conflits)
  • 3-4× plus long à développer
  • Non recommandé en V1
